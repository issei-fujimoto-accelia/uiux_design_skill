# セルフチェック

モック（または実装）を、品質基準に達するまでラウンドを重ねて改善する。
合格点、比較対象、最大ラウンド数は `UI_GUIDELINES.md` の5節に従う。書かれていなければ、合格点 8、最大5ラウンドとする。

## 評価軸と採点基準

各軸を10点満点で採点する。点数の意味は全軸で共通にする。合格ラインの点数だけが付き続けることを防ぐため、点数ごとに根拠を書く。

| 点 | 意味 |
|---|---|
| 4 | 崩れ、欠落、誤りがある |
| 6 | 崩れはないが、汎用テンプレートの水準。この製品である理由が見えない |
| 8 | 意図が一貫して伝わる。比較対象と並べて遜色のない箇所が多い |
| 10 | 比較対象を上回る点を、具体的に挙げられる |

| 軸 | 見ること | 主な根拠 |
|---|---|---|
| A. 目的への適合 | 各 FLW を目標の手数で終えられるか。各画面の主タスクが1つに見えるか | UX_STRUCTURE.md 1〜2節、PSN-N |
| B. 情報設計 | P1 が最初の画面内にあるか。階層とまとまりが読み取れるか | UX_STRUCTURE.md 5節、principles#hierarchy、#gestalt |
| C. 視覚の完成度 | 文字組み、余白のリズム、整列、トークンの一貫性 | UI_GUIDELINES.md 6節 |
| D. 状態の網羅 | 空、読み込み中、エラー、極端なデータ、権限の各状態が設計されているか | UX_STRUCTURE.md 2節 |
| E. 操作と動き | 押下の反応、遷移の意図、reduced-motion での代替 | UI_GUIDELINES.md 8節、principles#motion-purpose |
| F. アクセシビリティ | コントラスト、タップ領域、フォーカスの見え方、読み上げの名前 | UI_GUIDELINES.md 9節、principles#contrast、#target-size |
| G. 独自性 | シグネチャーとコンセプトが表れているか。使わない表現を避けているか | UI_GUIDELINES.md 1、3節 |

## ラウンドの手順

1. 撮影する：`python3 ../design-mock/scripts/shoot.py --root <プロジェクト> --out docs/work/design/rounds/NN/shots`。ダークモードがあれば `--theme dark` でも撮る。
2. 機械チェックを行う：`design_check.py all`（ERROR 0件）、`tokens.py contrast`（NG 0件）、shoot.py のページのエラー0件。
3. 自己採点する：軸ごとに点数、根拠（画面と箇所）、改善点を書く。比較対象のサイトを並べて見る。
4. 独立採点を行う（毎ラウンド必須）：実装の文脈を持たないサブエージェントに、スクリーンショット、`UI_GUIDELINES.md`、`UX_STRUCTURE.md`、本書だけを渡して採点させる。作業の経緯や自己採点は渡さない。サブエージェントを使えない環境では、新しいセッションで同じ材料を渡す。
5. 判定する：自己採点と独立採点の差が2点以上の軸は、低い方を採用する。
6. 改善する：低い軸から順に直す。直す先は design-mock の「指摘の反映」と同じ（文書 → モック）。
7. 記録する：`docs/work/design/rounds/NN/review.md`。

## 合格条件

- 全軸が合格点以上
- 自己採点と独立採点の差が全軸で1点以内
- 前のラウンドで挙げた改善点が解消済み
- 機械チェックがすべて0件

最大ラウンド数に達しても合格しない場合は、未達の軸、理由、次の打ち手を記録し、ユーザーの判断を仰ぐ。

## 記録の形式

```markdown
# Round NN（YYYY-MM-DD）対象：mock | impl

| 軸 | 自己 | 独立 | 採用 | 根拠 | 改善点 |
|---|---|---|---|---|---|
| A | 7 | 6 | 6 | FLW-1 が4手（目標3手）。SCR-2 の確認が冗長 | SCR-2 と SCR-3 を統合する案 |

機械チェック：design_check ERROR 0 / contrast NG 0 / ページのエラー 0 / 小さいタップ領域 0
前ラウンドの改善点：解消 3 / 未解消 0
判定：不合格（A、G が基準未満）
```
