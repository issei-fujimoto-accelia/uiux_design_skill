# プラットフォームごとの慣習

対象プラットフォームごとの、利用者が期待する操作と配置の慣習。モックは HTML による近似であり、ネイティブ実装の仕様ではない。
慣習から外れる判断をする場合は、`UI-N` に理由を書く（`principles#jakob`）。

## 比較

| 項目 | Web | iOS（Apple HIG） | Android（Material 3） |
|---|---|---|---|
| 主要なナビゲーション | ヘッダーのナビ。モバイル幅では下部タブかメニュー | 下部のタブバー（3〜5項目） | 下部のナビゲーションバー（3〜5項目）。大画面はナビゲーションレール |
| 戻る | ブラウザの戻る。画面内の戻るリンク、パンくず | 左上の戻るボタン、画面左端からのスワイプ | システムの戻る（ジェスチャーまたはボタン）。上部アプリバーの戻る |
| 主要な操作 | 画面内のボタン | ナビゲーションバー右上、または画面下部 | FAB、または画面下部 |
| 一時的な選択や詳細 | モーダル、ドロワー | シート（下から出る） | ボトムシート、ダイアログ |
| 破壊的な操作の確認 | ダイアログ | アクションシート、アラート | ダイアログ |
| 通知の一時表示 | トースト | バナー（アプリ内の独自実装が多い） | スナックバー（取り消しを含められる） |
| 最小のタップ領域 | 24×24 CSS px（WCAG AA） | 44×44 pt | 48×48 dp |
| 標準の書体 | 指定した Web フォントか system-ui | SF Pro（system-ui） | Roboto（system-ui） |

## モックでの扱い

- 画面の上下は、端末の安全領域を考慮する（`env(safe-area-inset-top)` など）。モックではビューポートの上下に余白で再現してよい。
- 戻るのジェスチャー、触覚フィードバック、ネイティブのピッカーは再現しない。再現しない旨を画面の注釈に書く。
- プラットフォームで配置が変わる画面は、プラットフォームごとに別の状態（`?platform=ios` など）として作る。

## 既定のビューポート

| 名前 | 大きさ（CSS px） | 想定 |
|---|---|---|
| ios | 390×844 | iPhone 14 / 15 |
| android | 412×915 | Pixel 7 |
| desktop | 1440×900 | ノート PC |

プロジェクトで変える場合は、`docs/skills.config.json` の `design.viewports` を更新する。
