# 共通部品（CMP）の仕様

共通部品は `UI_GUIDELINES.md` の7節に `CMP-N` で定義し、詳細を `docs/D2/components/CMP-N.md` に書く。モックの部品カタログと実装の部品は、この詳細設計に従う。

## 共通部品にする基準

次のどれかに当たるものを共通部品にする。

- 2画面以上で使う
- 状態（押下、無効、エラーなど）を持ち、見た目の一貫性が重要
- アクセシビリティの扱い（フォーカス、読み上げ）が決まっている必要がある

1画面だけで使う領域は、`data-ui="SCR-N/<名前>"` として画面側に置く。

## 書く場所

| 内容 | 場所 |
|---|---|
| ID、名前、用途、使う画面、理由、由来 | `UI_GUIDELINES.md` の7節（一覧） |
| 構成、受け取る値、状態と変種、大きさ、動き、アクセシビリティ | `docs/D2/components/CMP-N.md`（雛形：[COMPONENT.template.md](COMPONENT.template.md)） |

詳細設計の各項目は、次のように下流で使われる。項目を省くと、下流の検査や実装が成り立たない。

| 項目 | 使われ方 |
|---|---|
| カスタム要素名 | モックの `defineComponent` の要素名と照合する |
| 構成の `data-ui` | モックと実装の部位の照合に使う |
| 受け取る値 | モックの属性名になる。実装の props の仕様になる |
| 状態と変種 | 部品カタログの `data-example` と照合する |
| 大きさと伸び縮み | 極端なデータの状態の確認に使う |
| アクセシビリティ | 実装の受け入れ条件になる |

## 網羅する状態

| 種類 | 状態 |
|---|---|
| 操作できる部品 | 通常、ホバー（ポインター環境）、押下、フォーカス、無効 |
| 処理を伴う部品 | 処理中、成功、失敗 |
| 入力部品 | 空、入力中、入力済み、エラー、読み取り専用 |
| 内容を表示する部品 | 通常、空、長い内容、読み込み中 |

モックの部品カタログでは、詳細設計の「状態と変種」のすべてを、`data-example="<名前>"` を付けた例として並べる。
