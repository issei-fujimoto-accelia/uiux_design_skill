# v0.1.0

最初の版。対応する contract：1。

## 追加

### スキル

- **design-foundation**：品質方針の解釈、ペルソナ（`PSN-N`）、利用状況、コンセプト、全体の規則（`UI-N`）をインタビューで決める。
- **design-structure**：操作シナリオ（`FLW-N`）、画面（`SCR-N`）、遷移、ナビゲーション、配置、操作方法、情報の優先度を決め、`UX_STRUCTURE.md` と画面の詳細設計（`screens/SCR-N.md`）を作る。
- **design-visual**：デザイントークン（`design-tokens.json`）と共通部品（`CMP-N`）を決め、部品の詳細設計（`components/CMP-N.md`）を作る。
- **design-mock**：Tailwind CSS v4 と Web Components（Light DOM）でモックを作る。状態、テーマ、プラットフォーム、注釈をクエリで切り替えられる。
- **design-review**：`check`（機械検査）、`self-check`（採点と独立採点による改善）、`conformance`（モックと実装の照合）。

### 詳細設計の書式

- **design-structure/references/SCREEN.template.md**：画面の詳細設計（基本、入口と出口、領域、状態、操作、文言）。領域の `data-ui` と状態の名前は、モックと実装にそのまま使う。
- **design-visual/references/COMPONENT.template.md**：部品の詳細設計（基本、構成、受け取る値、状態と変種、大きさと伸び縮み、動き、アクセシビリティ、規則と理由）。

### 契約と設定

- **design-foundation/references/CONTRACT.md**：base_skill と疎結合に組み合わせるための取り決め（設定ファイル、配置、ID、`data-ui`、実装側の義務）。
- **design-foundation/assets/skills.config.json**：設定ファイルの雛形。

### スクリプト（標準ライブラリのみ。撮影と照合は playwright を使う）

- `design-visual/scripts/tokens.py`：トークン → Tailwind の `@theme`、素の CSS 変数、コントラストの検査。
- `design-mock/scripts/mock_build.py`：モックの配置とビルド。
- `design-mock/scripts/mock_index.py`：画面の一覧と注釈の生成。
- `design-mock/scripts/shoot.py`：全画面・全状態の撮影、ページのエラー、24px 未満のタップ領域の検出。
- `design-review/scripts/design_check.py`：ID の重複・未定義・由来と理由の欠落、詳細設計の必須の節と列、モックと詳細設計の一致（状態、領域、部品の要素名と属性、カタログの例）、トークン外の値。
- `design-review/scripts/ui_diff.py`：`data-ui` による不足・未設計・個数・スタイルの差の検出。
